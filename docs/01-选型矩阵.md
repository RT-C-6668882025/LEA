## 二、逐仓库要点

### 1. CoderLambert/filevista — 放弃
- 格式覆盖：React 组件，号称 20+ 格式（PDF/DOCX/PPTX/XLSX/EPUB/RTF/Markdown/代码/图片/音视频/ZIP/CSV/SVG/HTML），纯浏览器端渲染、无需上传服务器；PDF/Office 为可选插件（npm 包 `@lamberl-lee/file-preview`）。
- Windows 兼容：纯前端库，与 Windows 无关，Electron 内可用。
- 离线能力：渲染在本地完成，离线可用（EPUB 等插件依赖随包打包）。
- 集成成本：API 设计友好、有中英文 locale；但仅 3 Stars、单人项目，成熟度与长期维护无保障。
- 许可证风险：**LGPL-3.0**。JS 场景下 LGPL 的"允许用户替换该库"义务与 Electron 打包（bundle/压缩混淆）存在合规灰色地带，需把该库保持为可独立替换的模块；对闭源分发虽非不可行，但引入额外合规负担。
- 结论：项目太早期 + LGPL 打包顾虑 → 放弃，持续观察。

### 2. mehuljariwala/react-doc-viewer — 观望
- 格式覆盖：PDF、DOCX（内联）、Excel、PowerPoint、Markdown、图片、视频、CSV 等 20+ 类型，含标注、搜索、暗色模式、拖放、缩略图、i18n。
- Windows 兼容：纯 React 组件，Electron 内可用。
- 离线能力：本地渲染，离线可用。
- 集成成本：开箱即用程度高，但 22 Stars、4 个 open issues，社区薄；与我们"自组合 PDF.js + marked"方案功能重叠。
- 许可证风险：Apache-2.0，无分发风险（注意保留 NOTICE）。
- 结论：许可证无问题但项目影响力小，MVP 自建方案更可控 → 观望。

### 3. harshpreet931/anyview — 观望
- 格式覆盖：PDF、DOCX、XLSX、PPTX、CSV、Markdown、代码、HTML、Jupyter notebook、图片；无 iframe、无上传、文件不出页面；PDF 支持文本选择、搜索高亮、8 种标注工具。
- Windows 兼容：纯 React 组件，Electron 内可用。
- 离线能力：本地渲染，离线可用。
- 集成成本：README 自述 v0.2、pre-1.0、actively evolving；6 Stars，API 可能大幅变动。
- 许可证风险：MIT，无分发风险。
- 结论：MIT 友好但太早期 → 观望，若后期成熟可替代部分自建工作。

### 4. readest/readest — 放弃（许可证）
- 格式覆盖：完整跨平台电子书阅读器（Tauri + Next.js），EPUB 等主流格式，功能丰富（25.5k Stars，社区成熟）。
- Windows 兼容：官方支持 Windows 安装包。
- 离线能力：本地阅读，离线可用。
- 集成成本：它是**完整应用**而非渲染库；抽取其渲染层（基于 foliate-js 系）改造成本高于直接用 foliate-js。
- 许可证风险：**AGPL-3.0**。若把其代码作为组件链接/集成进我们的客户端并以 EXE 分发，**整个衍生作品须以 AGPL 向用户开放源码**（含网络使用条款的类 GPL 义务）；对计划闭源/商业分发的本项目不可接受。作为独立应用推荐用户另装没有问题，但不可嵌入。
- 结论：AGPL → 放弃集成。

### 5. mbret/prose-reader — 备选
- 格式覆盖：EPUB 3.3（严格按规范）、漫画 CBZ/CBR、PDF、纯文本，通过 enhancer 机制可扩展新格式；framework-agnostic SDK（非 React 绑定）。
- Windows 兼容：纯浏览器端渲染引擎，Electron 内可用。
- 离线能力：本地解析渲染，离线可用。
- 集成成本：TypeScript、npm 发包（`@prose-reader/core`）、文档站齐全（doc.prose-reader.com）；但 29 Stars、52 open issues，默认分支为 `develop`，API 稳定性弱于 foliate-js 在 Foliate 正式版中的验证度。
- 许可证风险：MIT，无分发风险。
- 结论：EPUB 渲染的活跃备选；若 foliate-js（6 个月未推送）后续维护恶化，可作为替换方案。

### 6. johnfactotum/foliate-js — 备选（EPUB 首选）
- 格式覆盖：EPUB、MOBI、KF8 (AZW3)、FB2、CBZ，PDF（实验性，需接 PDF.js）；纯 JS、模块化、**无硬依赖**、不必整本书载入内存。
- Windows 兼容：纯浏览器端，使用原生 ES Modules、无构建步骤，Electron 内直接 import 可用。
- 离线能力：本地渲染，离线可用；注意事项——IDPF 字体去混淆的 SHA-1 依赖 Web Crypto，需 secure context（Electron 的 `file://`/自定义协议下需验证或自传 SHA-1 实现）。
- 集成成本：README 明示"库本身不稳定，API 随时可能变"，且**从未发过正式版**，建议以 git submodule 引入；已被 Foliate（Linux 桌面阅读器）多个稳定版本实战使用，核心解析层可靠性有背书。
- 许可证风险：MIT，无分发风险。
- 结论：EPUB/电子书渲染首选备选；接受"无正式版 + API 变动"代价，锁定 submodule 版本可控。

### 7. mozilla/pdf.js — 选用
- 格式覆盖：PDF 渲染事实标准（Firefox 内置），文本层、注释、表单、搜索能力完整。
- Windows 兼容：纯 JS + 少量 WASM/worker，Electron/Chromium 内完美运行。
- 离线能力：完全本地渲染，离线可用（预置 standard_fonts 与 cmaps 即可覆盖 CJK 文档）。
- 集成成本：API 稳定（`pdfjs-dist` npm 包），文档与生态最全；体积约 1-2 MB 级，可接受。
- 许可证风险：Apache-2.0，无分发风险（保留 NOTICE）。
- 结论：**选用**，MVP 的 PDF 渲染组件。

### 8. MrUjjwalG/movi-player — 观望
- 格式覆盖：浏览器直接播放 MKV/HEVC/AV1/4K HDR/多音轨等 `<video>` 原生不支持的格式，Web Component（`<movi-player src="...">`），无转码无服务端；JS bundle 50-410KB + WASM 约 1.8-3.2MB。
- Windows 兼容：纯前端（WASM 解码），Electron 内可用。
- 离线能力：WASM 与资源随包打包后离线可用；CDN 引用方式需改为本地引用。
- 集成成本：npm 包 `movi-player`，接入方式极简（一个自定义元素）；但 82 Stars 的新项目，解码能力（尤其软解 4K）的 CPU 占用与稳定性需实测。
- 许可证风险：Apache-2.0，无分发风险。
- 结论：作为"Chromium 原生不支持的格式"（MKV/HEVC/AV1）的潜在增强件，列为观望，待实测后决定是否进入第三阶段。

### 9. zhw2590582/ArtPlayer — 备选
- 格式覆盖：全功能 HTML5 视频播放器 UI（弹幕、字幕、画中画、倍速、截图、缩略图预览等），配合 hls.js/flv.js/mpegts.js 等可扩展协议；解码本身走浏览器 `<video>`。
- Windows 兼容：纯 JS，无框架依赖，Electron 内可用。
- 离线能力：本地库文件即可，离线可用。
- 集成成本：4,135 Stars、3 天前仍有提交，文档齐全（artplayer.js.org），API 简洁，接入成本低。
- 许可证风险：MIT，无分发风险。
- 结论：播放器增强（UI/控制层/字幕/弹幕）首选备选；MVP 先用 Chromium 原生 `<video>`，第三阶段引入。

### 10. mpv-player/mpv — 放弃
- 格式覆盖：全能本地媒体播放器（C 实现），格式覆盖远超浏览器。
- Windows 兼容：官方支持 Windows（原生构建/libmpv）。
- 离线能力：完全离线。
- 集成成本：**高**。需要随 EXE 分发 libmpv 原生动态库 + 进程间/嵌入式渲染（render API）集成，体积与崩溃面增大，且解码器链路涉及大量第三方 GPL 组件。
- 许可证风险：GitHub `spdx_id=NOASSERTION`；仓库 `Copyright` 文件原文核实：**mpv 整体默认 GPLv2+**，仅在构建时以 `-Dgpl=false` 剔除 GPL 专用文件才可按 LGPLv2.1+ 授权，且官方明示"使用该开关本身不自动构成 LGPL 授权"，仍需自行核验文件清单。对我们而言：链接/捆绑默认构建 = 触发 GPL 传染义务，与闭源分发冲突。
- 结论：GPL + 原生集成成本 → 放弃；浏览器原生 + WASM（movi-player）路线替代。

### 11. hakimel/reveal.js — 备选
- 格式覆盖：HTML 幻灯片框架（Markdown 幻灯片、代码高亮、演讲者视图、导出等）。
- Windows 兼容：纯前端，Electron 内可用。
- 离线能力：库文件本地化后完全离线。
- 集成成本：72k Stars、生态成熟、文档全；把 `.pptx` 转为 reveal 的能力不在本仓库（需另议，MVP 不承诺 PPTX），用于"AI 生成的 HTML/Markdown 幻灯片"渲染场景契合。
- 许可证风险：MIT，无分发风险。
- 结论：幻灯片渲染备选，第三阶段引入。

### 12. tldraw/tldraw — 放弃（许可证）
- 格式覆盖：无限画布/白板 SDK（React），绘图、图形、手写等。
- Windows 兼容：纯 React，Electron 内可用。
- 离线能力：本地可用。
- 集成成本：SDK 成熟但为商业开源（source-available）模式，带 License Key 机制。
- 许可证风险：GitHub `spdx_id=NOASSERTION`；仓库 `LICENSE.md` 原文核实为**自定义 "tldraw license"**：明确 (a) **禁止在 Production Environment 使用**（含向最终用户/公众提供功能的部署），(b) **禁止将软件或其修改作为独立产品分发**（只能作为另一应用的一部分捆绑），(c) 不得禁用/干扰 License Key 强制机制，(d) 分发须附许可证全文；商业/替代许可需向 tldraw 付费。我们的客户端 = 面向最终用户的生产部署 + EXE 分发，直接落入限制范围。
- 结论：白板非核心需求 + 许可证不可接受 → 放弃；若第三阶段需要画布，另评估 MIT 的 excalidraw 等。

### 13. tauri-apps/tauri — 备选（桌面壳）
- 能力：Rust 壳 + 系统 WebView（Windows 上为 WebView2），安装包小（约 3-10 MB 级）、内存占用低，前端生态通用。
- Windows 兼容：官方一等支持，依赖系统 WebView2（Win10/11 一般已内置）。
- 离线能力：打包后完全离线。
- 集成成本：**本机当前无 Rust 工具链**（rustc/cargo + MSVC 均未装），构建链路需先搭环境；渲染引擎随系统 WebView2 版本漂移，一致性验证成本高于自带 Chromium 的方案；前端↔Rust IPC 有学习成本。
- 许可证风险：Apache-2.0，无分发风险。
- 结论：技术上是优秀的壳，但与当前团队环境（有 Node 24、无 Rust）不匹配 → 备选，若未来追求包体/内存优化再切换。

### 14. electron/electron — 选用（桌面壳）
- 能力：自带 Chromium + Node.js 的桌面壳，渲染一致性最好，前端生态直接复用；Node 24 本机已就绪，零新增工具链。
- Windows 兼容：官方一等支持；electron-builder/NSIS 产出 EXE 安装包链路成熟。
- 离线能力：完全离线（注意：所有渲染库随包本地化，运行期不依赖 CDN）。
- 集成成本：最低；代价是安装包大（约 80-150 MB 级）、内存占用高——对"轻量"目标的取舍：包体大但开发/维护成本最低，MVP 优先级下可接受。
- 许可证风险：MIT，允许闭源商业分发；分发时遵守其许可与商标惯例即可（用自有应用名与图标）。
- 结论：**选用**，MVP 桌面壳。

## 三、最终选型建议

### MVP（第一阶段）
| 层 | 选择 | 许可证 | 理由 |
|----|------|--------|------|
| 桌面壳 | **Electron** | MIT | 本机有 Node 24、无 Rust 工具链；渲染一致性好；EXE 打包链路成熟 |
| PDF | **PDF.js** (`pdfjs-dist`) | Apache-2.0 | 事实标准、当日仍活跃、本地化后离线 |
| Markdown | **marked + DOMPurify** | MIT / Apache-2.0 或 MPL-2.0 | marked 轻量解析，DOMPurify 消毒防 XSS；两者均不在本轮 14 仓库清单内，纳入依赖前按 npm 包元数据复核许可证 |
| 图片 / 音视频 | **Chromium 原生能力**（`<img>`/`<video>`/`<audio>`） | 随 Electron (MIT) | 零额外依赖，覆盖 jpg/png/webp/gif/svg、mp4/webm 等 |
| MCP Server | 自研 Node stdio Server（随安装包内置） | 自有 | 豆包桌面版支持 stdio command/args 方式拉起（见第四节），Node 实现无第三方许可证负担 |

MVP 原则：渲染组件合计依赖少、全部宽松许可证、全部可本地化离线运行。

### 第三阶段扩展
| 能力 | 首选 | 备选 | 说明 |
|------|------|------|------|
| 电子书（EPUB/MOBI/CBZ） | **foliate-js** (MIT) | prose-reader (MIT) | foliate-js 无正式版、API 不稳定，用 submodule 锁版本；其 6 个月未推送，若停更则切换 prose-reader |
| 幻灯片 | **reveal.js** (MIT) | — | 渲染 AI 生成的 HTML/Markdown 幻灯片 |
| 播放器增强 | **ArtPlayer** (MIT) | — | 进度缩略图/字幕/弹幕/倍速等 UI 增强 |
| MKV/HEVC/AV1 等浏览器不支持的格式 | — | movi-player (Apache-2.0, WASM) | 先实测性能（软解 CPU 占用），达标再引入 |
| 桌面壳优化 | — | Tauri (Apache-2.0) | 若包体/内存成为硬指标，先补 Rust+MSVC 工具链再评估 |

### 明确放弃及理由
- **readest（AGPL-3.0）**：集成即触发整应用源码开放义务，与闭源分发冲突；且它是完整应用而非库。
- **mpv（GPLv2+ 默认，LGPL 需特殊构建且不自动成立）**：GPL 传染 + libmpv 原生集成成本高；用 Chromium 原生 + WASM 路线替代。
- **tldraw（自定义 tldraw license）**：明文禁止生产环境使用、禁止独立产品分发，商用需购买授权；白板非核心需求。
- **filevista（LGPL-3.0）**：项目仅 3 Stars、单人早期项目，叠加 LGPL 在 JS 打包下的替换义务，收益不抵风险。
- **react-doc-viewer / anyview**：许可证无碍（Apache-2.0 / MIT），但均为小众/pre-1.0，与 MVP 自组合方案重叠，列观望不纳入。

## 四、豆包桌面版 MCP 接入调研

> 调研方法：WebSearch + 第三方文档/教程抓取，调研日期 2026-10-24。**字节官方未见公开的、成体系的豆包桌面版 MCP 配置文档**，以下结论以第三方来源交叉验证为主，个别细节需实测确认。

### 4.1 配置方式
- 入口（第三方教程一致描述）：豆包**桌面版**左侧「**技能 · 连接器 · 伙伴**」→ 右上角「**新建**」→「**新建自定义连接器**」。来源：葡萄城技术团队教程（CSDN，发布于 2026-09-09）、滴答清单帮助文档。
- 支持两种传输：
  1. **HTTP（远程 MCP URL）**：填 HTTPS 端点 + 自定义 Headers（如 token）。已由 2026-09 教程实证。
  2. **本地命令（stdio，command/args/env）**：需使用**提供本地 MCP 命令配置的桌面入口**，可填启动命令（如 `npx`/`uvx`/我们的 exe）与参数、环境变量。已由 CZUR 接入文档（open.czur.com/ai/mcp/doubao）实证其可行性。
- 添加后需「**保存 → 信任 → 启用**」：未信任的连接器不会被调用（多个来源提及）。

### 4.2 JSON 示例格式
本地 stdio 方式（与 Claude Desktop 等主流格式一致的 `mcpServers` 结构，CZUR 文档实证豆包接受该结构）：

```json
{
  "mcpServers": {
    "lea": {
      "command": "C:\\Program Files\\LEA\\mcp-server.exe",
      "args": ["--stdio"],
      "env": {},
      "disabled": false
    }
  }
}
```

HTTP 远程连接器方式（葡萄城教程示例结构）：

```json
{
  "mcpServers": {
    "spreadjs-mcp": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": { "token": "你的 token" }
    }
  }
}
```

### 4.3 注意点
1. **仅桌面版支持本地命令入口**：只接受远程 URL 的入口无法启动本地 stdio Server；网页版不支持本地 MCP。第三方文档明确提示"请使用提供本地 MCP 命令配置的桌面入口"，且不同版本菜单名称可能不同。
2. **未能核实**：本地命令入口是否需要特定版本/灰度、当前版本的确切菜单位置，以及豆包是否暴露本地 `mcp.json` 配置文件路径——官方文档未公开，建议拿到豆包桌面版后**实测**，并把实测截图补入本文档。
3. **对我们产品的落地建议**：
   - 安装包内置 MCP Server（Node/EXE，stdio 传输），安装时把命令路径写死为绝对路径，规避 `npx` 依赖网络与 Node 环境的不确定性（豆包侧无需用户装 Node）。
   - 提供一键配置：安装器附带"添加到豆包"脚本/说明页，直接给出可粘贴的 JSON 片段，降低用户配置成本。
   - 文档中同时给出 HTTP 模式说明（若未来提供局域网/远程调用场景），但离线优先承诺下以 stdio 为主。
